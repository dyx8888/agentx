## ADDED Requirements

### Requirement: 系统预设八大电商数字职位
系统 SHALL 提供八个预设的电商数字员工职位（6 保障型 + 2 增长型），每个职位 MUST 有明确的职责描述、能力边界、默认工具集、Skill 工作流、LLM 模型策略、RAG 注入策略和协作上下游关系。

#### Scenario: 管理员查看可用职位列表
- **WHEN** 管理员访问职位列表页面
- **THEN** 系统返回八个预设职位及其描述、类型标签（保障型/增长型）和能力列表

#### Scenario: 企业按需订阅职位
- **WHEN** 企业管理员选择订阅一个或多个职位
- **THEN** 系统为该企业创建对应的 Agent 实例，自动配置默认工具、Skill、推荐模型和 RAG 注入策略

### Requirement: 品牌商务（Brand BD）——保障型

品牌商务 MUST 负责达人营销全流程，是企业对外合作的核心角色。

**职责边界**：
- 达人搜索与筛选：按品类、粉丝量级、互动率等维度搜索匹配达人
- 合作邀约管理：生成个性化邀约话术，管理邀约发送-接受-拒绝状态
- 样品寄送跟进：向仓储物流发起寄送指令，跟踪物流状态
- 到货提醒与内容催更：检测样品签收后向达人发送开箱提醒，跟进内容产出
- 效果数据复盘：汇总达人合作数据（播放量/互动/转化），生成 ROI 报告
- 达人关系维护：定期回访、节日问候、长期合作档期锁定

**每日工作流**：
```
需求确认 → 达人搜索 → 深度分析 → 智能匹配 → 邀约发送（审核）
→ 样品跟进 → 到货提醒 → 内容催更 → 效果复盘 → 关系维护
```

**默认工具集**：
- `search_kols`：达人搜索（对接抖音星图 API / Mock 降级）
- `generate_outreach`：生成个性化邀约话术（RAG 注入品牌话术库）
- `check_delivery_status`：查询样品配送状态
- `generate_arrival_script`：生成到货提醒/开箱提醒私信
- `generate_performance_report`：生成达人合作效果复盘报告
- `generate_strategy_suggestion`：基于品类数据的达人策略建议
- `kol_relationship_manager`：达人关系管理（历史合作记录、档期追踪）

**Skill 工作流**：
- `kol_screening.md`：达人筛选评估完整流程（需求确认→大规模搜索→深度分析→智能匹配→推荐）
- `campaign_planning.md`：新品推广策划（市场分析→达人策略→内容策略→执行排期→预算测算）
- `batch_outreach.md`：批量邀约管理（分批发送→状态追踪→A/B 测试话术效果）
- `sample_tracking.md`：样品全流程跟进（发起→运输中→已签收→提醒→催更）
- `performance_review.md`：达人效果复盘（数据汇总→ROI 计算→达人分级→优化建议）

**协作关系**：
- 上游：无（自主发起任务）
- 下游：内容运营（达人确认后触发内容协作）、仓储物流（样品寄送指令）、数据分析（效果数据汇总）
- 共享：将达人筛选结果、合作协议状态写入 CompanyContextBus Layer 3

**LLM 模型策略**：
- 主模型：DeepSeek-V3（日常搜索、话术生成、报告撰写）
- 复杂策略：DeepSeek-R1（大型营销活动策划、多达人组合策略）
- RAG 注入：品牌话术库、达人合作历史、成功案例模板

**审核级别**：
- 达人邀约话术 → 强制审核（对外发送内容）
- 样品寄送指令 → 强制审核（涉及物流成本）
- 效果复盘报告 → 推荐审核
- 达人搜索 → 自动通过

#### Scenario: 品牌商务完成达人筛选后触发内容运营协作
- **WHEN** 品牌商务完成达人筛选并企业主确认合作达人
- **THEN** 系统自动向内容运营 Agent 发送协作请求，附送达人信息、产品信息和合作要求

#### Scenario: 品牌商务发起样品寄送
- **WHEN** 品牌商务确认达人合作后需要寄送样品
- **THEN** 系统生成样品寄送指令→推送企业主审批→批准后自动向仓储物流 Agent 发起寄送任务

#### Scenario: 品牌商务进行效果复盘
- **WHEN** 达人完成内容发布后
- **THEN** 品牌商务通过数据分析 Agent 获取效果数据，自动生成 ROI 复盘报告并写入 CompanyContextBus

### Requirement: 内容运营（Content Operator）——保障型

内容运营 MUST 负责多平台内容创作与排期管理，是企业内容输出的核心角色。优先自营号内容，兼顾达人合作内容。

**职责边界**：
- 内容需求分析：接收品牌商务/企业主的推广需求，拆解为具体内容任务
- 热点趋势调研：实时追踪各平台热点话题和内容趋势
- 创意策划：结合产品卖点和热点制定内容创意方向
- 脚本/文案创作：撰写短视频脚本、图文文案、标题、话题标签
- 内容排期管理：制定多平台内容日历，管理发布时间线
- 直播脚本撰写：为直播活动撰写整场脚本（暖场→产品介绍→互动→逼单→收尾）
- 简单视频剪辑：调用外部工具完成基础剪辑（裁剪、拼接、转场、字幕）
- 内容优化：基于数据反馈持续优化内容策略

**多平台管理**：通过 PlatformContextRouter 为每个经营平台维护独立上下文沙箱，避免信息混杂。

**每日工作流**：
```
需求接收 → 热点调研 → 创意策划 → 脚本/文案创作 → 内容审核（推荐）
→ 排期入历 → 发布 → 数据追踪 → 优化迭代
```

**默认工具集**：
- `generate_script`：生成短视频脚本（RAG 注入品牌话术+平台风格）
- `generate_content_plan`：生成多平台内容排期计划
- `trend_analysis`：热点话题抓取与分析
- `competitor_content_analysis`：竞品内容策略分析
- `content_calendar_manager`：内容日历管理（发布排期、状态追踪）
- `live_stream_script_generator`：直播脚本生成（分阶段撰写）
- `video_editor_bridge`：视频剪辑工具桥接（调用外部剪辑工具）
- `multi_platform_publisher`：多平台内容发布适配

**Skill 工作流**：
- `content_creation.md`：内容创作全流程（需求分析→热点调研→创意策划→脚本撰写→优化审核）
- `platform_adaptation.md`：跨平台内容适配（同一主题适配抖音/小红书/淘宝/拼多多的不同风格）
- `hot_trend_tracking.md`：热点趋势追踪（实时监控→热度评估→内容结合）
- `content_calendar_management.md`：内容日历管理（排期规划→发布调度→冲突检测）
- `live_stream_script.md`：直播脚本全流程（主题策划→环节设计→话术撰写→物料清单）
- `batch_content_generation.md`：批量内容生成（同产品多版本素材批量产出）

**协作关系**：
- 上游：品牌商务（达人内容需求）、供应链选品师（新品推广需求）
- 下游：智能投流专员（提供投放素材）、视觉设计（封面/素材需求）、数据分析（内容效果数据）
- 共享：将内容产出、排期计划写入 CompanyContextBus Layer 3

**LLM 模型策略**：
- 主模型：DeepSeek-V3（日常脚本、文案、排期）
- 创意策划：DeepSeek-R1（大型营销活动创意、跨平台内容策略）
- 多模态：GPT-4V/多模态模型（视频内容理解、竞品素材分析）
- RAG 注入：品牌话术库、平台内容风格模板、历史爆款内容模式

**审核级别**：
- 直播脚本 → 强制审核（对外实时内容，影响大）
- 日常视频脚本 → 推荐审核
- 内容排期 → 推荐审核
- 热点调研 → 自动通过

#### Scenario: 内容运营收到品牌商务的协作请求
- **WHEN** 内容运营 Agent 收到来自品牌商务的协作任务（含达人信息、产品信息和合作要求）
- **THEN** 系统加载达人信息、产品信息和品牌话术库作为 RAG 上下文，进入 Plan-Execute-Reflect 循环生成定制脚本

#### Scenario: 内容运营处理多平台内容需求
- **WHEN** 企业同时在抖音和小红书运营，需要为同一产品创作内容
- **THEN** PlatformContextRouter 分别激活抖音沙箱和小红书沙箱，独立生成适配各平台风格的内容

#### Scenario: 内容运营请求视觉设计协作
- **WHEN** 内容运营完成脚本创作后需要视频封面
- **THEN** 系统自动向视觉设计 Agent 发送协作请求，附带脚本摘要和视觉风格需求

### Requirement: 数据分析（Data Analyst）——保障型

数据分析 MUST 负责企业经营数据的采集、计算、分析和告警，是所有 Agent 的数据中枢。

**职责边界**：
- 多源数据采集：对接平台 API（抖音罗盘、蝉妈妈、淘宝生意参谋等）+ 聚合 CompanyContextBus 其他 Agent 产出
- 指标计算：通过 MetricsEngine 确定性计算核心经营指标
- 趋势分析：同比/环比趋势、异常检测、归因分析
- 报告生成：日报/周报/月报/活动专题报告
- 策略建议：基于数据分析的运营优化建议
- 异常告警：数据异常自动推送 Dashboard 和相关 Agent
- 竞品对标：行业 benchmark 对比分析

**每日工作流**：
```
数据采集（定时/触发）→ 数据清洗 → 指标计算（MetricsEngine 确定性）
→ 异常检测 → 趋势分析 → 报告生成 → 告警推送 → 建议输出
```

**默认工具集**：
- `data_collection`：多平台数据采集（经 PlatformAdapter）
- `metrics_calculation`：核心指标确定性计算（MetricsEngine）
- `anomaly_detection`：多维度异常检测（规则+统计算法）
- `report_generator`：结构化报告生成
- `dashboard_api`：Dashboard 数据看板 API
- `competitor_benchmark`：竞品对标分析
- `attribution_analysis`：归因分析（销量波动原因定位）

**Skill 工作流**：
- `performance_analysis.md`：经营效果分析（数据采集→整理→分析→洞察→建议）
- `trend_forecast.md`：趋势预测（历史数据分析→季节性调整→预测模型→置信区间）
- `anomaly_alert.md`：异常告警（阈值检测→归因分析→告警分级→推送→跟进）
- `weekly_report.md`：周报生成（数据汇总→同比环比→亮点/问题→建议）
- `campaign_report.md`：活动专题分析（活动前后对比→ROI 计算→渠道归因→优化建议）
- `competitor_benchmark.md`：竞品对标（行业数据拉取→差距分析→机会识别）

**MetricsEngine 确定性指标体系**：
- 销售指标：GMV、客单价、转化率、复购率
- 流量指标：UV、PV、停留时长、跳出率
- 投放指标：ROI、CPA、CTR、CVR
- 内容指标：播放量、互动率、完播率、涨粉率
- 服务指标：响应时长、解决率、好评率、退货率

**协作关系**：
- 上游：所有 Agent（接收各类产出数据）
- 下游：所有 Agent（提供数据分析和建议）、老板 Dashboard（数据看板+告警推送）
- 异常告警推送规则：库存异常→品牌商务+仓储物流；转化异常→智能投流+内容运营；服务异常→客服

**LLM 模型策略**：
- 日常分析：DeepSeek-V3（指标解读、报告撰写）
- 复杂策略：DeepSeek-R1（深度归因分析、策略建议生成）
- 核心指标计算：MetricsEngine 确定性计算（零 LLM 依赖，占比 80%+）
- RAG 注入：历史经营数据趋势、行业 benchmark、同类企业对比

**审核级别**：
- 策略建议（影响经营决策）→ 推荐审核
- 日常报表 → 自动通过
- 异常告警 → 自动通过（信息推送，不涉及执行）

#### Scenario: 数据分析生成周报
- **WHEN** 企业主或定时任务请求生成本周经营数据报告
- **THEN** MetricsEngine 从各平台 Adapter 拉取原始数据→确定性计算核心指标→LLM 生成分析叙述→输出结构化报告

#### Scenario: 异常检测触发告警
- **WHEN** MetricsEngine 检测到某款产品转化率同比下跌超过 30%
- **THEN** 系统同时向老板 Dashboard（WebSocket 推送）和智能投流专员、内容运营 Agent 推送告警，附带归因分析初步结果

### Requirement: 客服专员（Customer Service）——保障型

客服专员 MUST 负责客户咨询应答、售后处理和评价管理，是企业对客服务的一线角色。

**职责边界**：
- 智能应答：基于 RAG 知识库自动回复客户咨询（产品、物流、售后政策）
- 意图识别：分类客户意图（咨询/投诉/售后/好评），路由到对应处理流程
- 售后处理：退货/换货/退款流程处理，协调仓储物流
- 评价管理：好评回复、中差评跟进和挽回
- 情绪感知：识别客户情绪升级信号，自动升级为人工处理
- 知识库维护：从对话中提取新问题，建议更新知识库
- 批量操作：活动期间批量回复、批量好评管理

**每日工作流**：
```
消息接入 → 意图识别 → 知识检索（RAG）→ 回复生成 → 安全审核（三级）
→ 发送 → 效果追踪 → 知识库更新建议
```

**默认工具集**：
- `customer_query_response`：客户咨询自动应答（RAG 增强）
- `after_sales_handling`：售后流程处理（退货/换货/退款）
- `review_management`：评价管理（好评回复/差评跟进）
- `order_query`：订单信息查询
- `sentiment_analysis`：客户情绪分析
- `auto_reply_template_manager`：自动回复模板管理
- `knowledge_base_maintainer`：知识库维护（新问题提取、答案建议）

**Skill 工作流**：
- `inquiry_handling.md`：咨询处理（意图识别→知识检索→回复生成→审核→发送）
- `after_sales_processing.md`：售后处理（问题分类→方案生成→协商→执行→回访）
- `review_management.md`：评价管理（监控→分类→回复→跟进→分析）
- `sentiment_escalation.md`：情绪升级（检测→评估→升级通知→人工接管）
- `knowledge_base_maintenance.md`：知识库维护（新问题发现→答案模板生成→人工确认→入库）
- `batch_customer_operation.md`：批量客户运营（批量通知、批量好评感谢、批量售后跟进）

**三级发送策略**：
| 置信度 | 策略 | 适用场景 |
|--------|------|---------|
| ≥0.95 | 静默发送 | 标准 FAQ、订单查询、物流查询 |
| 0.80-0.95 | 批量确认 | 一般售后、投诉处理 |
| <0.80 + 售后/投诉/补偿 | 逐条审核 | 退款协商、大额赔付、危机投诉 |

**协作关系**：
- 上游：仓储物流（物流状态信息）
- 下游：仓储物流（退换货处理指令）、品牌商务（客户反馈和产品问题）
- 共享：客户常见问题写入 CompanyContextBus Layer 2（知识库）

**LLM 模型策略**：
- 日常客服：DeepSeek-V3
- 简单 FAQ：轻量模型降成本
- RAG 注入：公司知识库（产品信息/售后政策/SOP/历史对话）- 强依赖 RAG
- 情绪分析：单独的情绪分析模型

**审核级别**：
- 静默发送（高置信度）→ 自动通过（事后可追溯）
- 批量确认 → 推荐审核
- 逐条审核（售后/投诉/补偿）→ 强制审核

#### Scenario: 客服专员处理售后请求
- **WHEN** 有客户提交售后请求（退货/换货/投诉）
- **THEN** 客服 Agent 查询订单信息→检索售后政策 RAG→按置信度分级发送策略处理→如需退换货则通知仓储物流协同

#### Scenario: 客服识别情绪升级
- **WHEN** 客户连续表达不满且情绪分析得分超过阈值
- **THEN** 系统自动将对话升级为人工处理状态，推送紧急通知到 Dashboard

### Requirement: 仓储物流（Warehouse Logistics）——保障型

仓储物流 MUST 负责库存管理、发货调度和物流跟踪，是企业供应链的执行角色。

**职责边界**：
- 库存监控：实时查询 ERP/WMS 系统库存状态，多仓库存汇总
- 发货调度：接收发货指令，生成发货单，选择最优仓库和物流渠道
- 物流跟踪：对接快递鸟/菜鸟等物流 API，实时追踪包裹状态
- 异常预警：物流延迟、丢件、库存告急等异常检测和通知
- 库存优化：基于销售趋势和季节性推荐安全库存和补货计划
- 退换货逆向物流：处理退换货的入库和质检流程
- ERP 数据同步：与企业 ERP/WMS 系统保持数据一致性

**每日工作流**：
```
库存巡检 → 订单处理（发货指令队列）→ 发货调度 → 物流跟踪
→ 异常检测 → 库存预警 → 库存优化建议 → ERP 同步
```

**默认工具集**：
- `inventory_check`：库存查询（ERP/WMS API 对接）
- `shipment_tracking`：物流轨迹跟踪（快递鸟/菜鸟 API）
- `logistics_alert`：物流异常预警
- `order_fulfillment`：发货单生成和执行
- `warehouse_allocator`：多仓智能调度分配
- `delivery_estimate`：预计送达时间计算
- `erp_sync_bridge`：ERP 系统数据同步桥接

### Requirement: 智能投流专员（Smart Ad Delivery Specialist）——增长型

智能投流专员 MUST 负责电商广告投放的策略制定、执行和优化，是企业流量获取和 ROI 优化的核心角色。

- 效果复盘：投放结束后产出分析报告，提炼投放经验

**每日工作流**：
```
投放策略 → 素材准备 → 计划创建（审核）→ 实时监控 → 智能调优
```
