## ADDED Requirements

### Requirement: Agent 间通过异步任务实现协作
Agent 间通信 SHALL 统一使用 schedule_task 模式：源 Agent 创建指向目标 Agent 的 Task 记录，目标 Agent 在自己的执行循环中拉取并处理。禁止使用同步 invoke 方式调用其他 Agent 的 LLM。

#### Scenario: 品牌商务完成任务后发起内容运营协作
- **WHEN** 品牌商务 Agent 完成达人筛选工作且企业主确认合作达人
- **THEN** 系统自动创建一条目标为"内容运营"的 Task，附送达人列表、产品信息和合作要求

#### Scenario: 目标 Agent 拉取属于自己的待处理任务
- **WHEN** 内容运营 Agent 启动新一轮工作循环
- **THEN** 系统从 Task 表中拉取 company_id 匹配且目标为自己、状态为 pending 的任务

#### Scenario: 选品确认触发多 Agent 联动
- **WHEN** 企业主批准供应链选品师的新品选品报告
- **THEN** 系统自动向品牌商务（达人推广规划）、内容运营（新品内容策划）、智能投流（投放策略规划）同时创建协作任务

### Requirement: CompanyContextBus 共享上下文总线（三层数据架构）

系统 MUST 维护一个 CompanyContextBus，承载公司级三层数据。Agent 在完成任务后将关键产出写入总线，其他 Agent 可以从总线读取同公司的上下文信息。

```
┌─────────────────────────────────────────────┐
│           CompanyContextBus                  │
├─────────────────────────────────────────────┤
│  Layer 1: 公司基础资料                        │
│  ├─ 品牌名/品类/经营平台/产品线                │
│  ├─ 更新频率: 极少                             │
│  └─ 隔离: company_id 行级隔离                  │
├─────────────────────────────────────────────┤
│  Layer 2: 公司知识库                          │
│  ├─ 产品信息/售后政策/品牌话术/SOP/供应商库     │
│  ├─ 更新频率: 低（手动维护或 Agent 建议）       │
│  └─ 注入方式: RAG 检索增强生成                 │
├─────────────────────────────────────────────┤
│  Layer 3: 公司经验记忆                        │
│  ├─ Agent 工作产出摘要/决策记录/审核反馈        │
│  ├─ 更新频率: 高（每次任务完成后自动写入）       │
│  └─ 注入方式: 上下文窗口 + RAG 混合检索         │
└─────────────────────────────────────────────┘
```

#### Scenario: Agent 完成任务后自动写入上下文
- **WHEN** 品牌商务完成达人筛选并写入上下文总线
- **THEN** 同公司的内容运营 Agent 在下一次执行时可以通过 RAG 检索到「当前正在处理的达人列表」作为上下文

#### Scenario: 跨公司上下文严格隔离
- **WHEN** 公司 A 的 Agent 尝试读取上下文总线
- **THEN** 系统只返回 company_id = A 的数据，不会泄露公司 B 的任何信息

#### Scenario: 不同 Agent 注入不同层级数据
- **WHEN** 客服 Agent 处理客户咨询
- **THEN** 系统自动注入 Layer 2（产品信息/售后政策 RAG）+ Layer 3（该客户的历史对话摘要）

### Requirement: 三级人工审核机制

所有 Agent 的任务产出 MUST 按风险等级分为三级审核。每个任务产出附带 `review_level` 字段。

| 级别 | 触发条件 | 处理方式 | 典型场景 |
|------|---------|---------|---------|
| **强制审核** (mandatory) | 对外发送内容、涉及金钱/合同、平台操作 | 必须人工批准后才执行，进入 pending_review 状态 | 达人邀约发送、广告投放计划、样品下单、退款处理 |
| **推荐审核** (recommended) | 重要但可逆的操作、策略建议 | 推送给用户，可一键通过或忽略，超时不阻塞 | 内容脚本、选品建议、设计稿、库存优化建议 |
| **自动通过** (auto) | 低风险查询、内部数据处理 | 自动执行，仅在 Dashboard 展示记录 | 数据查询、库存检查、报告生成、趋势调研 |

#### Scenario: 强制审核——邀约话术等待确认
- **WHEN** 品牌商务 Agent 生成达人邀约话术且 review_level=mandatory
- **THEN** 话术进入 pending_review 状态→推送 Dashboard 和 PWA 通知→企业主批准/修改/拒绝→批准后执行发送

#### Scenario: 推荐审核——内容脚本可一键通过
- **WHEN** 内容运营生成视频脚本且 review_level=recommended
- **THEN** 脚本推送到待审核列表→企业主可一键通过或忽略→24 小时未处理自动标记为已忽略

#### Scenario: 强制审核超时升级
- **WHEN** 强制审核任务超过 4 小时未被处理
- **THEN** 系统升级告警→重复推送通知→Dashboard 红色高亮标记

### Requirement: 协作链自动编排

系统 SHALL 支持定义 Agent 间的协作链规则（哪个 Agent 完成后触发哪个 Agent）。协作链可被选品确认等事件批量触发。

**预设协作链**：

```
选品确认 ──→ 品牌商务（达人规划）
         ──→ 内容运营（新品内容策划）
         ──→ 智能投流（投放策略）

达人确认 ──→ 内容运营（达人脚本定制）
         ──→ 仓储物流（样品寄送，审核后）

内容完成 ──→ 视觉设计（封面/素材需求）
         ──→ 智能投流（投放素材）

售后处理 ──→ 仓储物流（退换货逆向物流）
```

#### Scenario: 协作链自动触发
- **WHEN** 企业主批准选品报告
- **THEN** 系统按预设协作链自动创建三条异步 Task，分别指向品牌商务、内容运营、智能投流

#### Scenario: 企业自定义协作链
- **WHEN** 企业主在设置页面修改协作链配置
- **THEN** 后续协作按新的链规则执行，不影响已创建的任务

### Requirement: 实时通知推送

当有新的协作任务、待审核项目或任务完成时，系统 SHALL 通过 WebSocket 向前端 Dashboard 和 PWA 推送实时通知。

#### Scenario: 协作任务创建时推送通知
- **WHEN** 内容运营 Agent 完成了一个由品牌商务发起的协作任务
- **THEN** 系统通过 WebSocket 向该公司的 Dashboard 推送通知："内容运营已完成达人脚本创作，等待审核"

#### Scenario: 数据异常告警同时推送多方
- **WHEN** 数据分析 Agent 检测到某产品转化率异常下跌
- **THEN** 系统同时推送：(1) Dashboard 告警通知、(2) 相关 Agent（智能投流+内容运营）作为协作文本注入上下文

### Requirement: 内容运营多平台上下文隔离

内容运营 Agent MUST 为每个经营平台维护独立的上下文沙箱，通过 PlatformContextRouter 在任务执行时自动切换。不同平台的上下文不得混合。

```
┌─────────────────────────────────────────────┐
│         PlatformContextRouter               │
├─────────────────────────────────────────────┤
│  ┌──────────┐ ┌──────────┐ ┌──────────┐     │
│  │ 抖音沙箱  │ │小红书沙箱 │ │ 淘宝沙箱  │    │
│  │ - 账号   │ │ - 账号   │ │ - 账号   │     │
│  │ - 内容史 │ │ - 内容史 │ │ - 内容史 │     │
│  │ - 数据   │ │ - 数据   │ │ - 数据   │     │
│  │ - 策略   │ │ - 策略   │ │ - 策略   │     │
│  └──────────┘ └──────────┘ └──────────┘     │
└─────────────────────────────────────────────┘
```

#### Scenario: 同一产品跨平台内容创作
- **WHEN** 企业同时在抖音和小红书运营，需要为同一产品创作内容
- **THEN** PlatformContextRouter 分别激活抖音沙箱和小红书沙箱，基于各自的内容史、数据、策略独立生成内容，不交叉污染

#### Scenario: 新增经营平台自动创建沙箱
- **WHEN** 企业在公司设置中添加新的经营平台（如拼多多）
- **THEN** 系统自动为内容运营创建拼多多上下文沙箱，初始化为空

### Requirement: 客服消息安全分级发送

客服 Agent 生成回复后 MUST 按置信度分级执行发送策略，确保高风险消息经过人工确认。

| 置信度 | 策略 | 延迟 | 适用场景 |
|--------|------|------|---------|
| ≥0.95 | 静默发送 | 即时 | 标准 FAQ、订单查询、物流查询 |
| 0.80-0.95 | 批量确认 | 汇总后推送 | 一般售后建议、投诉初步回应 |
| <0.80 | 逐条审核 | 每条审核 | 复杂售后、退款协商 |
| 任意 + 高风险标记 | 逐条审核 | 每条审核 | 大额赔付、危机投诉、法律风险 |

#### Scenario: 高置信度自动回复
- **WHEN** 客户询问"我的订单什么时候发货"且 RAG 检索置信度 ≥0.95
- **THEN** 系统直接返回物流查询结果并发送，事后在 Dashboard 展示记录

#### Scenario: 低置信度触发逐条审核
- **WHEN** 客户要求全额退款并附带投诉语气，置信度 <0.80
- **THEN** 系统生成回复后进入 pending_review 状态→企业主审核修改→批准后发送

### Requirement: MCP 工具三级权限控制

Agent 使用的 MCP 工具 MUST 按操作风险分为三级权限，不同级别有不同的授权要求。

| 权限级别 | 操作类型 | 授权方式 | 示例工具 |
|---------|---------|---------|---------|
| 只读 | 查询/搜索/分析 | 自动授权 | search_kols, inventory_check, trend_analysis |
| 写入 | 创建/修改数据 | 需人工确认 | campaign_create, order_fulfillment |
| 外部操控 | 操控外部软件 | 显式授权 + 操作日志审计 | video_editor_bridge, erp_sync_bridge |

#### Scenario: 只读工具自动执行
- **WHEN** Agent 调用 search_kols 搜索达人
- **THEN** 系统自动授权执行，无需人工确认

#### Scenario: 外部操控工具需显式授权
- **WHEN** Agent 调用 video_editor_bridge 操作外部剪辑软件
- **THEN** 系统弹窗要求企业主确认授权范围（操作类型、文件范围）→批准后执行→全程记录操作日志
